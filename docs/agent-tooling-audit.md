## 社区源码与模板取舍

| 项目                          | 对本模板的启示                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| unibest                       | 根 `AGENTS.md` 按任务指向架构、平台和流程文档，另列框架参考 Skill。沿用这种分工，项目入口保持简短，把 spec 写作与验收示例放进命中的 Skill。unibest 用配置生成 `pages.json`，Koi 则直接维护该文件，两者应各自注明事实源。[unibest 项目规则](https://github.com/unibest-tech/unibest/blob/8277fab1eccf7464d4fe63310309ad5c35cc2ce9/AGENTS.md)                                                                                                                                                                                                                                                                        |
| Agent Skills 与 Vercel Skills | 格式规范用 `name`、`description` 发现 Skill，执行时才加载正文和相对路径资源。Vercel 安装器给 Codex、Cursor 使用 `.agents/skills`，给 Claude Code 使用 `.claude/skills`。保留单一工作流正文，同时从干净生成物逐个检查入口能读到该正文及引用文件。[格式规范](https://github.com/agentskills/agentskills/blob/83021e2be457a9b6679148719c1f6074f0ad975e/docs/specification.mdx) · [客户端目录映射](https://github.com/vercel-labs/skills/blob/57217cf86ba38148a57af9e90d14a4c049558330/src/agents.ts)                                                                                                                  |
| uni-helper Skills 与 MCP      | 项目附带的框架参考对应 2026-01-30 的文档快照。社区服务在 `search-docs-by-Uniapp-official` 被调用时才打开向量表并使用嵌入模型；查询依赖和失败点与 Skill 本地阅读不同。写作时可先查本地参考，需要 API 细节时核对对应官方文档，记录实际使用的来源。[参考快照](https://github.com/uni-helper/skills/blob/15909ff061a38819ad45ad2d89db3b66938eaf84/skills/uniapp/GENERATION.md) · [工具注册与调用](https://github.com/uni-helper/mcp/blob/675646de5b28394080cf689e40d242c83fc96721/src/server/index.ts) · [检索实现](https://github.com/uni-helper/mcp/blob/675646de5b28394080cf689e40d242c83fc96721/src/docs/index.ts) |
| Model Context Protocol        | 协议把发现工具的 `tools/list` 和执行工具的 `tools/call` 定义为两个操作。离线生成测试可捕获配置遗漏、版本漂移；实测报告应写明对应服务能启动、能列工具，以及哪项查询真正返回了结果。[工具协议](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/2bbace557bbf2cb5d03d6f9b48905415cd7607b0/docs/specification/2025-11-25/server/tools.mdx)                                                                                                                                                                                                                                                            |

GitHub Spec Kit 的规格模板把每个用户故事关联到可独立执行的验收场景。Koi 的写作 Skill 因此以现有首页重试为例，让作者写清初始条件、一次操作和可观察结果，并分别记录用例单测和端上观测。新增项目 Skill 时采用 Anthropic 示例中的名称、描述和正文结构。[Spec Kit 的规格模板](https://github.com/github/spec-kit/blob/f2010547121b3351e4923fe467205079e4593a32/templates/spec-template.md) · [Anthropic 的 Skill 模板](https://github.com/anthropics/skills/blob/e4bb5d960d87126ff3b3a8af1a104b7db67560ba/template/SKILL.md)
